# Anti-Fraud: выявление мошеннических операций моделью LightGBM II

*English version: [README.en.md](README.en.md)*

**Демо онлайн:** [huggingface.co/spaces/dina-05-fff/anti-fraud-lightgbm-demo](https://huggingface.co/spaces/dina-05-fff/anti-fraud-lightgbm-demo)
— модель проверяет синтетические операции, ничего устанавливать не нужно.

## Цель проекта

Построить модель, которая по данным банковской операции оценивает **риск мошенничества** и находит как можно больше
мошеннических операций при небольшом числе ложных тревог, и показать её работу в приложении.

**Данные** — соревнование [IEEE-CIS Fraud Detection](https://www.kaggle.com/competitions/ieee-fraud-detection) (Kaggle):
590 540 операций с известным исходом, из них мошеннических — около 3,5%. Классы сильно несбалансированы, поэтому
обычная accuracy здесь бесполезна: модель, которая называет все операции легальными, уже получает 96,6%.

## Итоговая модель — LightGBM II

Градиентный бустинг LightGBM: 4628 деревьев, 458 признаков. Модель выдаёт **оценку риска** от 0 до 1; операция с
оценкой не ниже порога **0,0486** считается **тревогой**.

| Метрика | Значение | Что означает |
|---|---|---|
| **AP** (average precision) — главная | **0,621** | средняя доля верных тревог при разных порогах; учитывает именно редкий класс. Случайная модель дала бы ≈0,034 |
| ROC-AUC | 0,919 | вероятность, что мошенническая операция получит оценку выше обычной (0,5 — монетка, 1 — идеал) |
| Recall (полнота) | 0,552 | какую долю мошеннических операций модель нашла |
| Precision (точность тревог) | 0,649 | какая доля тревог оказалась верной |
| F1 | 0,597 | баланс Precision и Recall |
| Найдено при 1% ложных тревог | 55% | если допустить 1 000 ошибочных тревог на 100 000 обычных операций |

**Матрица ошибок** (порог 0,0486, 118 108 операций проверочной выборки):

| | Модель: тревога | Модель: обычная |
|---|---|---|
| **Мошенничество** | найдено 2 243 | пропущено 1 821 |
| **Обычная операция** | ложные тревоги 1 213 | верно 112 831 |

## Как проверялась модель

Операции упорядочены **по времени**: модель учится на прошлом и проверяется на будущем, как в реальной работе.

```
|-------------- первые 80% операций (обучающие) --------------|---- последние 20% ----|
|        Обучение — 401 567        |    Holdout — 70 865       | Validation — 118 108  |
|        модель учится             |  выбор настроек и порога  | итоговая оценка,      |
|                                  |                           | 42 дня                |
```

- **Обучение** — на этих операциях модель видит правильные ответы и учится.
- **Holdout** (внутренняя проверка) — модель на них не учится; здесь сравнивались настройки и выбирался порог.
- **Validation** (проверочная выборка) — последние 42 дня; здесь ничего не подбиралось, на ней измерены метрики выше.
- Тестовая выборка соревнования (Test) не использовалась: правильных ответов для неё нет.
- Признаки истории считаются **только по более ранним операциям**; правильный ответ (`isFraud`) в признаки не входит.

## Как подбирались настройки

Настройки (гиперпараметры) задаются до обучения: насколько сложные деревья строить, насколько сильно штрафовать
модель за сложность и когда остановить обучение. Все варианты сравнивались на внутренней проверке (Holdout).

1. **Остановка обучения по AP** — деревья добавляются, пока растёт AP на внутренней проверке. Это дало главный
   прирост: AP с 0,577 до 0,655.
2. **Финальный выбор из 4 вариантов** (число листьев 127 / 255 × регуляризация 0,5 / 5). Лучший — 255 листьев,
   регуляризация 0,5 (AP 0,672 на внутренней проверке). Это и есть LightGBM II.
3. **Порог 0,0486** выбран там же по максимуму F1.

## Что важно модели

Топ признаков по важности (Gain): почтовый домен получателя, признаки Vesta (V258, C1, C13, C14, V294), коды карты
(card1, card2), сумма операции и собственный признак истории — максимальная сумма прошлых операций той же группы
карта+адрес. Лучше всего модель находит мошенничество в продуктах C и R; сложнее всего — массовый продукт W и
операции без данных об устройстве.

## Модель хранится приватно

- Файла модели в репозитории **нет**. Модель (`lgbm_B_full.txt`, ≈130 МБ) хранится в **приватном** репозитории
  Hugging Face Hub: её публичное распространение не разрешено, пока не подтверждено, что правила соревнования это допускают.
- При старте приложение скачивает модель из `HF_REPO_ID` по токену `HF_TOKEN` и проверяет SHA-256
  (`config/app_config.json`), число деревьев (4628) и имена признаков. При любом несовпадении прогноз не выполняется.
- Вместо скачивания можно указать локальный файл модели переменной `MODEL_PATH` (имеет приоритет).
- Имя репозитория и токен в коде не хранятся; секреты задаются в `.streamlit/secrets.toml` (файл в `.gitignore`,
  образец — `secrets.toml.example`) или в переменных окружения.

## 458 признаков модели

Полный список и типы — `config/feature_schema.json`; шаблон заголовков — `templates/features_template.csv`.

| Группа | Число | Состав |
|---|---|---|
| Исходные признаки операции | 391 | TransactionAmt, ProductCD, card1–card6, addr1–addr2, dist1–dist2, P_/R_emaildomain, C1–C14, D1–D15, M1–M9, V1–V339 |
| Исходные признаки устройства (identity) | 40 | id_01–id_38, DeviceType, DeviceInfo |
| Простые производные | 7 | has_identity, условный час и день недели, число пропусков в группах V / D / M / id |
| Понятные признаки | 12 | группа суммы, тип и категория карты, почтовый провайдер и частота домена, совпадение доменов, ОС, бренд и модель устройства |
| История группы card1+addr1 | 8 | число, средняя / минимальная / максимальная сумма прошлых операций, время с предыдущей операции и их интервалы |
| **Итого** | **458** | 41 категориальный, 417 числовых |

Смысл многих исходных признаков (C, D, V, M, id_*) организаторы соревнования не раскрыли.

## Входной и выходной CSV (основное приложение)

**Приложение не строит признаки из исходных транзакций** — на вход подаётся таблица с уже готовыми 458 признаками.

| Правило | Поведение |
|---|---|
| Кодировка | UTF-8 (BOM допускается); разделитель «,», десятичная точка «.» |
| Столбцы | ровно 458 признаков с именами из шаблона и, по желанию, `TransactionID` |
| Отсутствующий или лишний столбец (в том числе `isFraud`) | ошибка |
| Другой порядок столбцов | столбцы переставляются по именам, выводится предупреждение |
| Пропуск | только пустая ячейка |
| Числовые признаки | число или пустая ячейка; иной текст — ошибка с номерами строк |
| Незнакомое значение категории | обрабатывается как пропуск, как при оценке модели; приложение показывает число таких значений |
| Размер | не более 50 000 строк, файл до 100 МБ |

Результат — файл `lgbm2_results_<SHA-256 модели, 8 символов>_thr<порог>.csv` со столбцами `row`, `TransactionID`
(если был во входе), `fraud_probability`, `predicted_class` (1 — тревога) и `threshold`.

Порог можно изменить в интерфейсе; качество при других порогах не проверялось. Оценки модели не откалиброваны:
это шкала риска для сравнения с порогом, а не точная вероятность.

## Запуск

Нужен Python 3.12.

```powershell
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
$env:MODEL_PATH = "<путь_к_lgbm_B_full.txt>"      # или HF_REPO_ID и HF_TOKEN
.venv\Scripts\streamlit run app.py --server.address 127.0.0.1
```

Демо локально: дополнительно задайте `FRAUD_PARAMS_DIR` (папка с параметрами признаков проекта) и запустите
`streamlit run demo/app_demo.py`.

На Linux и macOS — те же шаги с `source .venv/bin/activate` и `export`.

## Тесты и проверка перед публикацией

```bash
pip install -r requirements-dev.txt
python -m pytest tests demo/tests -q
python tools/check_publish_safety.py
```

Тесты, которым нужны модель или локальные данные, без них пропускаются. `check_publish_safety.py` проверяет, что в
git не попадут модели, данные, CSV (кроме шаблона), токены, абсолютные пути и файлы больше 1 МБ.

## Ограничения

- Метрики получены на одном разбиении по времени (проверочная выборка — 42 дня). На этой выборке проверялись и
  другие варианты моделей при разработке, поэтому результат может быть немного оптимистичным; проверки на совсем
  новых данных (Test) не было.
- Один seed; порог выбран по F1 — реальная стоимость пропуска и ложной тревоги неизвестна.
- Модель обучена на данных одного периода и формата IEEE-CIS; перенос на другие данные не проверялся.
