# Anti-Fraud: прогноз мошенничества моделью LightGBM II (Streamlit)

*English version: [README.en.md](README.en.md)*

Веб-приложение на Streamlit. Оно оценивает вероятность мошенничества для операций, у которых **уже подготовлены
458 признаков**, финальной моделью исследовательского проекта по данным соревнования
[IEEE-CIS Fraud Detection](https://www.kaggle.com/competitions/ieee-fraud-detection) (Kaggle).

**Модель — LightGBM II:**
- 4628 деревьев, 458 признаков;
- обучена на первых 80% операций по времени;
- порог по умолчанию 0.0486;
- на отложенной по времени выборке Validation (42 дня): AP 0.621, ROC-AUC 0.919, F1 0.597.

> **О метриках.** Все показатели качества в этом README и в интерфейсе получены на выборке **Validation**.
> Эта выборка уже использовалась при разработке и сравнении моделей, поэтому показатели **не являются независимой
> оценкой на Test**. Тестовая выборка соревнования (Test) **не использовалась** для оценки качества модели.

**Что делает приложение:**
1. принимает CSV с подготовленными признаками;
2. проверяет имена, число, порядок и типы всех 458 признаков;
3. считает вероятность мошенничества и класс по порогу;
4. показывает сводку и даёт скачать результаты.

> **Приложение не выполняет preprocessing исходных транзакций.** Частотные признаки, история группы операций
> card1+addr1 и другие производные признаки должны быть построены заранее тем же кодом, что при обучении модели.
> Исходные таблицы соревнования (transaction / identity) как входные данные не принимаются.
> Ноутбуки исследовательского проекта, в которых строятся признаки, **в этот репозиторий не входят**.

## Модель хранится приватно — без доступа приложение не запустится

- Файла модели в репозитории **нет**. Модель (`lgbm_B_full.txt`, ≈130 МБ) хранится в **приватном** репозитории
  Hugging Face Hub. Её публичное распространение не разрешено, пока не подтверждено, что правила соревнования это допускают.
- При старте приложение скачивает модель из репозитория `HF_REPO_ID` по токену `HF_TOKEN` и проверяет SHA-256
  (`config/app_config.json`), число деревьев (4628) и имена признаков. При любом несовпадении прогноз не выполняется.
- **Без доступа к модели приложение не запустится.** Нужно одно из двух:
  - `HF_REPO_ID` (например, `владелец/имя-репозитория`) и `HF_TOKEN` (токен только на чтение этого репозитория) —
    переменные окружения или секреты Streamlit;
  - локальный файл модели, путь к которому задан переменной `MODEL_PATH` (имеет приоритет).
- Имя репозитория и токен в коде не хранятся. В `config/app_config.json` поле `hf_repo_id` — заглушка; оно
  используется, только если `HF_REPO_ID` не задан, и заглушка значением не считается.
- Секреты задаются в `.streamlit/secrets.toml` (файл в `.gitignore`; образец — `secrets.toml.example`) или
  в переменных окружения.
- Модель загружается один раз на процесс (`st.cache_resource`).

## 458 признаков модели

Полный список и типы — `config/feature_schema.json`; шаблон заголовков — `templates/features_template.csv`.

| Группа | Число | Состав | Источник |
|---|---|---|---|
| Исходные признаки transaction | 391 | TransactionAmt, ProductCD, card1–card6, addr1–addr2, dist1–dist2, P_/R_emaildomain, C1–C14, D1–D15, M1–M9, V1–V339 | таблица transaction соревнования (без TransactionID, TransactionDT, isFraud) |
| Исходные признаки identity | 40 | id_01–id_38, DeviceType, DeviceInfo | таблица identity (соединение по TransactionID; у операций без identity — пусто) |
| Простые производные | 7 | has_identity, hour, weekday, n_missing_V / D / M / id | по одной строке |
| Интерпретируемые признаки | 12 | amount_group, is_large_amount, card_type_group, card_category_group, P_/R_email_provider, P_/R_email_domain_freq, email_same_domain, device_os, device_brand, device_model_family | правила и статистики, рассчитанные на обучающей части |
| История группы card1+addr1 | 5 | group_prev_transactions, group_prev_amount_mean / min / max, group_time_since_prev | по операциям той же группы **строго раньше по времени** (группа — приближённая группа операций, а не ID клиента) |
| Производные истории | 3 | group_first_operation, group_time_since_prev_bin, group_prev_amount_mean_bin | из признаков истории |
| **Итого** | **458** | из них 41 категориальный, 417 числовых | |

Смысл многих исходных признаков (C, D, V, M, id_*) организаторы соревнования не раскрыли.

## Входной CSV

| Правило | Поведение приложения |
|---|---|
| Кодировка | UTF-8 (BOM допускается); разделитель «,», десятичная точка «.» |
| Столбцы | ровно 458 признаков с именами из шаблона и, по желанию, `TransactionID` |
| Отсутствующий признак | **ошибка** — нулями или чем-либо ещё не заполняется |
| Лишние столбцы | ошибка (в том числе `isFraud` — истинная метка в приложение не подаётся) |
| Повторяющиеся имена столбцов | ошибка |
| Другой порядок столбцов | столбцы переставляются по именам, затем порядок проверяется на точное совпадение с моделью; выводится предупреждение |
| Пропуск | **только пустая ячейка** |
| Числовые признаки (417) | конечное число или пустая ячейка; любой другой текст («NA», «nan», «inf», «1,5») — ошибка с номерами строк |
| Категориальные признаки (41) | текст сохраняется как есть: «NA», «None», «–», «≥1000» — это значения, а не пропуски |
| Значение категории, которого не было при обучении | модель обрабатывает его как пропуск — так же, как при оценке модели; приложение показывает, сколько таких значений, и ничего не подменяет |
| Повторяющиеся `TransactionID` | предупреждение |
| Размер | не более 50 000 строк, файл до 100 МБ |

Числовые значения следует записывать с полной точностью float64: при округлении прогноз может отличаться от расчёта
в исследовательском проекте.

## Выходной CSV

Имя файла: `lgbm2_results_<первые 8 символов SHA-256 модели>_thr<порог>.csv`, например
`lgbm2_results_f413c46f_thr0.0486.csv`.

| Столбец | Смысл |
|---|---|
| `row` | номер строки во входном файле (с 1, без заголовка) |
| `TransactionID` | идентификатор из входного файла (только если столбец был во входе) |
| `fraud_probability` | вероятность мошенничества по модели, от 0 до 1 |
| `predicted_class` | 1 — тревога (вероятность ≥ порога), 0 — нет |
| `threshold` | порог, при котором получен класс |

## Порог классификации

- **По умолчанию 0.0486** (точно 0.04861665045870177). Он выбран по максимуму F1 на внутренней временной проверке
  внутри обучающей части и перенесён на итоговую модель. На Validation при этом пороге: Precision 0.649,
  Recall 0.552, F1 0.597. Это результаты на Validation, использовавшейся при разработке и сравнении моделей,
  а не независимая оценка на Test.
- Модель обучалась с весами классов (мошенничество ≈3.5% операций), калибровка вероятностей не проводилась.
  Поэтому `fraud_probability` — оценка для ранжирования и сравнения с порогом, а не откалиброванная доля мошенничества.
- Порог можно изменить в интерфейсе. Фактический порог показывается рядом с числом тревог и записывается в файл
  результатов. **Качество при других порогах не проверялось.** В реальной работе порог выбирают по стоимости
  пропуска мошенничества и ложной тревоги или по допустимой нагрузке на проверку — эти величины здесь неизвестны.

## Запуск

Нужен Python 3.12.

**Windows (PowerShell):**
```powershell
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
$env:MODEL_PATH = "<путь_к_lgbm_B_full.txt>"      # или: $env:HF_REPO_ID = "<владелец>/<репозиторий>"; $env:HF_TOKEN = "<токен>"
.venv\Scripts\streamlit run app.py --server.address 127.0.0.1
```

**Linux и macOS:**
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
export MODEL_PATH="<путь_к_lgbm_B_full.txt>"      # или: export HF_REPO_ID="<владелец>/<репозиторий>" HF_TOKEN="<токен>"
streamlit run app.py --server.address 127.0.0.1
```

С приватным Hugging Face Hub: скопируйте `.streamlit/secrets.toml.example` в `.streamlit/secrets.toml` и впишите
`HF_REPO_ID` и `HF_TOKEN` — или задайте их переменными окружения.

## Тесты

```bash
pip install -r requirements-dev.txt
python -m pytest tests -q
```

| Файл | Что проверяет | Что нужно |
|---|---|---|
| `test_validation.py` | правила чтения и проверок на синтетических таблицах | ничего |
| `test_model_loader.py` | выбор источника модели: `MODEL_PATH`, `HF_REPO_ID`, заглушка в конфиге (без сети) | ничего |
| `test_publish_safety.py` | скрипт проверки публикации находит запрещённое содержимое | ничего |
| `test_categories.py` | обработка 41 категориального признака совпадает с поведением модели | модель (`MODEL_PATH`) |
| `test_app_smoke.py` | интерфейс: запуск, ошибки ввода, порог, имя файла результатов | модель; для полного сценария — локальные данные |
| `test_local_acceptance.py` | прогнозы по CSV совпадают с расчётом исследовательского проекта (допуск 1e-12), в том числе после перестановки столбцов | модель и локальные данные (`LOCAL_DATA_DIR`) |

Без модели и локальных данных соответствующие тесты пропускаются. Ожидаемые значения для проверок на реальных
данных в коде тестов не хранятся — они считаются во время запуска из локального эталона (`LOCAL_DATA_DIR`).

`tools/export_features_local.py` готовит локальный CSV признаков для приёмочного теста **из данных
исследовательского проекта**, которые сюда не входят. Корень проекта задаётся через `--project-root` или переменную
`PROJECT_ROOT`; результат пишется только в папку вне репозитория.

## Проверка перед коммитом

`python tools/check_publish_safety.py` показывает, какие файлы git включит в репозиторий, и ищет в них запрещённое:
- модели, данные, CSV (кроме шаблона), архивы;
- абсолютные пути, токены, ключи, пароли, адреса почты;
- файлы больше 1 МБ.

Он также проверяет, что правила `.gitignore` работают. Без установленного git есть упрощённый режим `--no-git`.

## Данные и лицензия

- Данные соревнования IEEE-CIS Fraud Detection **не распространяются** вместе с кодом: в репозитории нет исходных
  строк, реальных признаков, словарей категорий и прогнозов по реальным данным. Использование данных регулируется
  правилами соревнования на Kaggle.
- **Лицензия MIT (файл `LICENSE`) распространяется только на исходный код этого приложения.** Она не распространяется
  на данные Kaggle, производные от них таблицы и обученную модель.

## Ограничения модели

- Оценка получена на одном временном разбиении и одной выборке Validation (42 дня). Эта выборка использовалась
  при разработке и сравнении моделей, поэтому оценка не является независимой оценкой на Test. Test для оценки
  качества модели не использовался.
- Один seed; порог выбран по F1, стоимость ошибок неизвестна.
- Модель обучена на данных одного периода; переносимость на более поздние периоды не проверялась.
